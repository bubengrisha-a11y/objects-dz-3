# Сервис объектов

Расширение `СчетаМагазина` для демонстрационной конфигурации «Библиотека стандартных
подсистем» 3.2.1. HTTP-сервис с корнем `objects` описывает, ищет, читает и создаёт
справочники и документы любого вида конфигурации; счёт на оплату покупателю — частный
случай, он создаётся тем же маршрутом.

Спецификация с границами (какие виды объектов поддерживаются, какие отклоняются, формат
ошибок): [`docs/superpowers/specs/2026-11-20-universal-objects-design.md`](docs/superpowers/specs/2026-11-20-universal-objects-design.md),
разделы «HTTP-контракт» и «Проверка и приёмка».

## Маршруты

| Маршрут | Что делает |
| --- | --- |
| `GET /types?q=<слово>` | находит справочники и документы по слову в имени или синониме |
| `GET /type?name=<Вид.Имя>` | описывает тип по метаданным: поля, обязательность, типы значений, табличные части |
| `GET /search?type=<Вид.Имя>&q=<строка>[&limit=<N>]` | ищет объекты типа; при обрезке по `limit` ставит `hasMore` |
| `GET /object?type=<Вид.Имя>&id=<uuid>` | читает объект: шапка и табличные части |
| `POST /object` | создаёт справочник или документ (документ — непроведённым); ошибки заполнения — `422` |

Ошибки всегда в одном формате: `{"error": {"code", "message", "details": [{"path", "message"}]}}`.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `СчетаМагазина.cfe` | расширение для загрузки в базу, выгружается скриптом `tools/load-extension` |
| `src/extensions/СчетаМагазина/` | исходники расширения (XML, формат Hierarchical) |
| `src/tests/objects.http` | запросы REST Client по маршрутам, в порядке сценария |
| `src/tests/.env` | адрес, авторизация и идентификаторы демо-данных для запросов |
| `tools/load-extension.cmd` | загрузка расширения в базу, обновление и выгрузка `.cfe` |
| `tools/bsl-check.py` | статическая проверка: синтаксис BSL и кодировка файлов |
| `docs/superpowers/` | спецификация и план сервиса |

## Как проверить

Нужны компьютер с платформой 1С:Предприятие 8.5.1.960 или новее, база из `1Cv8_demo.dt`,
опубликованная на веб-сервере, и VS Code с расширением REST Client. Проверку в базе
выполняет пользователь: в среде разработки ИИ-агента платформы 1С нет, поэтому агент
проверяет исходники только статически.

1. Заполнить `src/tests/.env`: `OBJECTS_URL` — адрес публикации вашей базы,
   `OBJECTS_AUTH` — заголовок авторизации. Идентификаторы демо-данных подходят для базы
   из `1Cv8_demo.dt`.
2. Закрыть Конфигуратор базы и загрузить расширение:

   ```
   tools\load-extension.cmd -InfoBase <каталог базы>
   ```

   Дополнительные параметры: `-User`, `-Password`, `-Platform` (путь к `1cv8.exe`). Скрипт
   загружает XML из `src/extensions/СчетаМагазина` в расширение, обновляет его в базе и
   выгружает свежий `СчетаМагазина.cfe` в корень репозитория.
3. Открыть `src/tests/objects.http` в VS Code и выполнить запросы сверху вниз (REST Client,
   «Send Request» над каждым). Под заголовком каждого запроса указан ожидаемый ответ
   (`# Ожидается: …`). Именованные запросы (`# @name`) нужны следующим за ними.
4. В 1С открыть созданные запросами партнёра и счёт на оплату покупателю; убедиться, что
   счёт не проведён.

Статическая проверка исходников перед коммитом (не заменяет проверку в базе):

```
python3 tools/bsl-check.py --fix
```

Последняя строка вывода — `OK: синтаксических ошибок нет, кодировка и переводы строк в порядке`.

## Что сдавать (по «Приёмке» задания)

- Спецификация с границами — `docs/superpowers/specs/2026-11-20-universal-objects-design.md`.
- Расширение, выгруженное в `СчетаМагазина.cfe` в корне репозитория.
- Файл запросов REST Client `src/tests/objects.http`: по запросу на каждый маршрут,
  создание справочника и документа; адрес и учётные данные — в `src/tests/.env`, не в самих
  запросах. Реальные значения `OBJECTS_AUTH` в сдаваемые материалы не включаются.
- Контрольный пример: скриншоты из 1С — партнёр и счёт на оплату покупателю, созданные
  запросами из файла; счёт не проведён.
